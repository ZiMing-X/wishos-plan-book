# 四要素速查 · 正反样例

> 供 `plan_book_check` 直接验证。判据源：`doc-plan-protocol` §S2 + `plan-template v1.5` §三点六 + `计划推进验证协议`。
> 本文件只做**写法样例**，不重述规程判据（避免同一事实两处声明）。

## 一 · 结构要求（机读）

1. 表头行须**同时含四键，且落在 4 个不同列**：`依赖` / `可并行` / `完成判定` / `门禁`（或 `depends_on` / `parallel_with` / `done_when` / `gate`）。
2. 表格其后每一行，四列都**必须有内容**；「无」写 `—`，**不等于**留空。
3. 全文须有**总门禁**声明（出现 `total_gate` 或「总门禁」字样）。

## 二 · 正样本（应判 `extractable`）

```markdown
| ID | 批次 | 依赖 | 可并行 | 完成判定 | 门禁 |
|:--|:--|:--|:--|:--|:--|
| **B1** | 规格冻结 | — | — | `spec.md` 落盘；20/20 样本双向一致 | 不一致 ⇒ 回炉 spec，不写库 |
| **B2** | 实现 | B1 | — | `tool --selftest` 退码 0；篡改必红 | rc≠0 ⇒ 回 B1，不进 B3 |
| **B3** | 压测 | B2 | — | 1,000 次并发零碰撞（日志计数=1000） | 出现重码 ⇒ 停，查锁 |

**总门禁（total_gate）**：`python tools/_gate.py` 退码 0 且 `--selftest` 退码 0
```

## 三 · 反样本（应判 `not_extractable`，且理由准确）

| 反样本形态 | 期望判定 | 理由锚 |
|:--|:--|:--|
| 某行 `门禁` 留空 | 🔴 not_extractable | 空格（键在但内容空） |
| 某行少写一列（行比表头短） | 🔴 not_extractable | 缺键（该行没有这一列） |
| 表头把四键挤在一个单元格（`四要素（依赖/可并行/完成判定/门禁）`） | 🔴 not_extractable | **缺表**（四键未分列） |
| 有表但全文无总门禁 | 🔴 not_extractable | 无总门禁声明 |
| 普通文档（无任何批次表） | 🔴 not_extractable | **缺表** —— 真阴性位：不得误诊为"表里缺键" |

## 四 · 写作要点（人读）

- **依赖 / 可并行**：ID 必须与批次表逐字一致；散文箭头（`A → B`）机器读不出。
- **完成判定**：写"文件路径 + 客观读数"，如 `产物登记.md 命中 12 行`、`退码 0`、`计数=1003`。
- **门禁**：写"不满足时做什么"，不是"不满足就失败"。默认三拍：回退修补 1 次 → 仍失败 → 挂起待人工确认。
- **总门禁**：命令 + 退码，可复跑；含一条 ⚪真阴性（好样本不该被误报）。
