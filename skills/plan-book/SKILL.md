# plan-book — 计划任务书（文档态计划）

**定位**：把「一个要跨会话跑、要交给别人接手、要事后能对账」的任务，先写成一份**任务书**再开工。
本技能＝**唯一入口**。机器态计划（JSON / MetaSkill）不归这里 —— 那是 `plan-template` → `plan-executor` → `plan-auditor` 那条线。

## 零 · 门槛触发（先判该不该写任务书）

| 情形 | 走法 |
|:--|:--|
| 单步任务 / 纯只读查询 / 即问即答 | ❌ **豁免**，直接做 |
| 3~8 步、单会话内完成、产出不需长期回溯 | 🟡 轻量计划（机器态），**不写任务书** |
| ≥3 批 **且**（跨会话 / 跨日 / 需长期回溯 / 需交接 / 涉批量外部文档） | ✅ **写任务书**，走本技能 |

**一句话判据**：*这个任务中断一天后，另一个人能靠这份文档接着跑吗？* 不能 ⇒ 别写任务书。

## 一 · 六步

| 步 | 做什么 | 出口（不满足不往下走） |
|:-:|:--|:--|
| **S1 打靶评估** | 把每个前提写成**可证伪命题**，用真实文件系统 / 真实数据逐条实测，**不推演** | 评估报告含假设打靶表（🟢成立/🔴推翻/🟡有条件/⚪未验证）+ 遗漏清单 + 诚实性声明 |
| **S2 四要素任务书** | 每批一行，四要素**可机械提取** | `plan_book_check` 判 `extractable` |
| **S3 冻结 + 执行记录** | 任务书只写"计划"，进度/实绩写**独立**执行记录文件 | frontmatter 有 `frozen` 与 `execution_log`；本体内不出现进度勾选 |
| **S4 逐批门禁** | 每批完成判定必须**重新实测**，实绩记执行记录 | 每批一行实绩：读数 + 时间 + 证据路径 |
| **S5 总门禁** | 机器可判的总门禁（命令 + 退码） | 总门禁命令退码 0 |
| **S6 复盘回流** | 偏差、教训、作废项各自回流；"记录之外"也要扫 | 复盘段落到盘；教训转成判据或技能，不停在"知道了" |

> 🔴 **铁律**：**"未验证"不得升级为"建议/结论"**。反例：评估报告已诚实标注某通道"未实测、可能翻转"，任务书却把它写成"必须做"并列为前置动作 ⇒ 后被更轻的方案全盘推翻，白绕一轮。

## 二 · 四要素（格式严格，因为要机读）

| 要素 | 文档态写法 | 禁 |
|:--|:--|:--|
| **前置依赖** | 每批一行 `依赖：B0,B1`（ID 与批次表**逐字一致**） | 只写散文箭头 |
| **可并行** | `可并行：<ID 列表>`，无则写 `—` | 留空；只写"可任意时点插入" |
| **完成判定** | `完成判定：<文件路径 + 客观读数（阈值/退码/计数）>` | 「完成了」「80%」等主观自评 |
| **推进门禁** | `门禁：<不满足时的动作>`；默认「回退修补 1 次 → 仍失败 → 挂起待人工确认」 | **留空**（＝无门禁，头号反模式） |

结构要求：表头须**同时含四键且分列**（`依赖/可并行/完成判定/门禁`，兼容 `depends_on/parallel_with/done_when/gate`）；
另须有**总门禁**声明（出现 `total_gate` 或「总门禁」字样）。`—` 表示"无"，**不等于留空**。

## 三 · 三条硬规则

1. **门禁必填** —— 任一行 `门禁` 留空 ⇒ **整份不受理**（不是瑕疵，是"没有门禁"）。
2. **计划本体冻结** —— 批红后不就地打勾改字；进度/实绩/偏差一律写独立执行记录；口径变了**起新版本**（v1.1），旧版保留可对账。
3. **总门禁机器可判** —— 必须是命令 + 退码，不是"人工确认完毕"。

## 四 · 工具

| 工具 | 用途 | 判据（缺一不可） |
|:--|:--|:--|
| `plan_book_check` | 校验一份 `.md` 的四要素是否可机械提取 | `status=extractable` **且** `placeholders=0` |
| `plan_book_new` | 生成任务书骨架（frontmatter + 四要素表 + 总门禁 + 冻结声明） | 生成件自身须过 `plan_book_check` |
| `plan_book_health` | 插件自检：技能文件 / 注册状态 / 三夹具 | `ok=true`：正样本过、负样本拦、无表文档"拦对理由" |

用法要点：
- 先 `plan_book_new` 落骨架 → 逐批填实质内容 → 跑 `plan_book_check`。
- `placeholders>0` ⇒ 结构过关但**实质未填**，此时不得宣称"任务书完成"（门禁全绿 ≠ 产物合规）。
- 校验是**结构**判据，不是**质量**判据：四要素齐全 ≠ 判据锚对。判据该怎么写，用 `criteria-design-standard`。

## 五 · 反模式（踩过的）

| # | 反模式 | 后果 |
|:-:|:--|:--|
| 1 | 门禁留空 | 出问题没有回退动作，等于无门禁 |
| 2 | 在任务书里就地打勾 / 改数字 | 计划与实绩混为一体 ⇒ 无法对账、无法复盘 |
| 3 | 完成判定写成主观自评 | 无法机器判 ⇒ 等于没有判据 |
| 4 | 总门禁写成"人工确认" | 人一忙就默认绿 |
| 5 | 把"未验证"升级成"必须做" | 把假设当事实，白绕一轮 |
